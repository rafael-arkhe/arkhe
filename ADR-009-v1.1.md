# ADR-009: Uso de Windmill como Orquestração Externa (Não-Runtime)

| Campo | Valor |
|---|---|
| ID | ADR-009 |
| Versão | 1.1 |
| Status | Proposto |
| Data | 2026-08-11 |
| Decisores | Arquiteto ARKHE |
| Contexto | ARKHE OS v1.2 — Fase 0, Semana 1 |
| Revisão | Integration Spike (Semana 18) |

## Contexto

O ARKHE OS v1.2 define 3 domínios de runtime distintos:
- **Domínio A** (`quantum-shadows`): Python 3.12 + Qiskit Aer + numpy/scipy (computação batch científica)
- **Domínio B** (`signal-hankel`): Rust + Verilator + AMD toolchain (síntese/simulação FPGA)
- **Domínio C** (`safe-core-policy`): Rust + `cargo` + `SandboxContract` (kernel de segurança)

A pergunta era se uma workflow engine (Windmill, Activepieces, n8n) poderia substituir ou integrar-se a esses runtimes.

## Decisão

**NÃO** substituir nenhum runtime por workflow engine.  
**SIM** usar Windmill AGPLv3 como **camada de orquestração externa estritamente opcional**, limitada a:
1. Scheduling de jobs batch (Dom A/B)
2. Notificações via webhook para operadores
3. Dashboards auto-generated para métricas do Integration Spike
4. Versionamento de scripts de orquestração (não do runtime científico)

> **⚠️ CLÁUSULA DE OPCIONALIDADE ESTRITA:** A remoção completa do Windmill não quebra, degrada ou altera qualquer funcionalidade core do ARKHE OS. Os domínios A, B e C operam independentemente. O Windmill é um componente descartável — se removido, o EvidenceBus (gRPC/AXI-Stream/shared memory) continua funcional, o SandboxContract continua operacional, e a latência p95 < 100ms continua medida no caminho crítico. Esta ADR não cria dependência arquitetural.

## Consequências

### Positivas
- Git sync nativo do Windmill versiona scripts de scheduling.
- Durable execution para notificações (não para computação científica).
- UI para operadores monitorarem estado dos domínios sem acesso ao runtime.

### Negativas / Guardrails
- Windmill **NÃO** substitui `EvidenceBus` (gRPC/AXI-Stream).
- Windmill **NÃO** implementa `SandboxContract` (fuel/epoch).
- Windmill **NÃO** executa código Rust do `safe-core-policy` como script versionável (binário apenas).
- Windmill **NÃO** é linkado como crate ou biblioteca ao workspace Rust do ARKHE — executa como processo separado via webhook/gRPC.
- Latência p95 < 100ms do ARKHE é medida no `EvidenceBus`, não na fila PostgreSQL do Windmill.
- **AGPLv3 está em blacklist de compliance corporativo em muitas organizações.** A aceitação do Windmill requer aprovação explícita da equipe Legal. Como o Windmill executa como processo separado (nunca linkado), o risco de contaminação de licença é mitigado, mas não eliminado. Se a equipe Legal rejeitar o AGPL, o Windmill é removido sem impacto funcional (ver cláusula de opcionalidade estrita acima).

## Alternativas Rejeitadas

| Alternativa | Razão de Rejeição |
|---|---|
| Activepieces no Domínio A | Categoria errada: visual builder para batch científico de 76.800 shots |
| n8n | Fair-code (SUL) — bloqueio comercial em cenários de redistribuição |
| Pipedream/Zapier | Cloud-only — viola Data Residency (princípio ARKHE v1.2) |
| Windmill como runtime dos domínios | Quebra SandboxContract, EvidenceBus, e latência p95 |
| Windmill linkado como crate Rust | Viola AGPLv3 + MIT/Apache boundary; risco legal inaceitável |

## Validação

Esta ADR será revisada no Integration Spike (Semana 18). Se qualquer invariante do ARKHE for violado pelo Windmill externo, a camada de orquestração será removida sem cerimônia. Critérios de remoção automática:
1. Latência do EvidenceBus degradada por overhead do Windmill.
2. Qualquer PR que injete Windmill/Activepieces no runtime dos domínios.
3. Rejeição de compliance Legal sobre AGPLv3.
4. Falha de reprodutibilidade por imagem Docker não pinada.
